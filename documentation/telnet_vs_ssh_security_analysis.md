# Telnet vs SSH Security Analysis

## 1. Overview & Theoretical Background

Remote management protocols allow network administrators to access command-line interfaces (CLIs) of routers and switches across local subnets or WAN links. The choice between **Telnet (RFC 854)** and **Secure Shell v2 (SSH RFC 4253)** represents the fundamental transition from legacy cleartext administration to modern encrypted network management.

---

## 2. Comprehensive Comparison Matrix

| Feature | Telnet Protocol | Secure Shell (SSH v2) |
| :--- | :--- | :--- |
| **TCP Port** | Port 23 | Port 22 |
| **Data Transmission Format** | Plaintext (ASCII) | Encrypted Ciphertext |
| **Authentication Vector** | Cleartext Username & Password | Asymmetric RSA Key Pair / Encrypted Credentials |
| **Integrity Checks** | None (Vulnerable to Tampering) | HMAC-SHA2 Integrity Verification |
| **Eavesdropping Risk** | **CRITICAL**: Captured easily via Wireshark / Packet Tracer Simulation | **PROTECTED**: Payloads appear as random cipher bytes |
| **Man-in-the-Middle (MitM)** | Vulnerable to Session Hijacking & Injection | Server Host Key Verification prevents spoofing |
| **Cisco IOS Prerequisite** | Basic `line vty` configuration | Requires Hostname, IP Domain-Name, & Crypto RSA Key |
| **Recommended Usage** | Deprecated / Lab testing only | Enterprise Industry Standard |

## 3. Cisco Packet Tracer Simulation Analysis

### 3.1 Telnet Capture Scenario (Port 23)
During Packet Tracer Simulation Mode, capturing packets generated by executing `telnet 192.168.10.1` on **PC-1** yields the following Protocol Data Unit (PDU) detail:

```
+-------------------------------------------------------------------+
| Telnet Packet Header (TCP Port 23)                                |
+-------------------------------------------------------------------+
| Payload Data:                                                     |
|   User:  a d m i n                                                |
|   Pass:  T e l n e t P a s s 1 2 3 !                              |
+-------------------------------------------------------------------+
```
* **Vulnerability Identified**: Every keystroke (username characters, password string, CLI commands executed) is transmitted as unencrypted ASCII bytes inside standard TCP payloads. Any rogue host or packet analyzer on the segment can reconstruct full credentials.

---

### 3.2 SSH Capture Scenario (Port 22)
Executing `ssh -l admin 192.168.10.1` on **PC-1** initiates an encrypted Diffie-Hellman key exchange followed by symmetric session encryption (AES-256):

```
+-------------------------------------------------------------------+
| SSH-2.0 Packet Header (TCP Port 22)                               |
+-------------------------------------------------------------------+
| Cipher Payload:                                                   |
|   7a 9f b2 14 e8 01 3c a7 89 ff d1 45 6b c2 10 9e ...             |
+-------------------------------------------------------------------+
```
* **Security Verification**: Even when packet captures log all PDUs, the encrypted payload prevents unauthorized actors from deciphering credentials, privilege mode passwords, or router configuration commands.

---

## 4. Cisco IOS Hardening Recommendations

1. **Disable Telnet Transport**: Enforce `transport input ssh` exclusively across all VTY lines.
2. **Key Length**: Utilize a minimum of 2048-bit RSA modulus (`crypto key generate rsa modulus 2048`).
3. **Session Idle Timeouts**: Configure `exec-timeout 10 0` to prevent abandoned open terminal sessions.
4. **Login Attempt Restrictions**: Implement `login block-for 60 attempts 3 within 30` to mitigate brute-force password guessing attacks.
